# Routing, security and reliability review — 2026-09-05

Baseline: `6633f19` (`main`, QuickRoute 1.16.0). This review includes corrective changes and new destination features. It is not an in-game certification or a completed Codex Security scan; that scan's native tools were unavailable in this session.

**Historical routing review:** this document preserves the initial routing review and its first implementation rounds. The assertion counts, performance measurements and simulator images below describe those rounds; they are not the latest verification results. The later [player workflow review](PLAYER-WORKFLOW-REVIEW-2026-09-05.md) records the five client-reported issues, additional adjacent defects, subsequent fixes and the combined simulator used for the final visual pass. Passing the initial tests did not establish that those player workflows were correct.

## Verdict

**The baseline does not fulfil its unrestricted “fastest route to any destination” promise.** A large passing mock suite concealed impossible transport links, incorrect flight-master state interpretation, omitted hearthstones and quest buttons which did not use the route calculation. The accompanying changes address these faults and improve useful coverage. The continuation adds the missing phase/unlock model, sourced shortcuts and destination data, and complete-tour ordering. The requested feature families are implemented; actual retail execution and universal world coverage are separate claims that the available evidence cannot certify.

“Fastest” means the minimum estimated cost in the modeled travel graph, subject to known methods and available state. It cannot mean a proven fastest navigable path over arbitrary terrain, inside every dungeon, through every phase and to every NPC. There is no terrain/navigation mesh in this addon; walk/fly costs approximate distances and travel speeds.

## Findings addressed

| Priority | Baseline defect and player impact | Correction and regression evidence |
|---|---|---|
| P1 | `ConnectViaContinentRouting` manufactured 240/300-second cross-continent travel without a portal, boat or other actual link. Disconnected same-continent zones also received invented travel times. | Remove fabricated edges and return no route for missing topology. Weighted zone search chooses elapsed time rather than the first fewest-hop path. `test_routing_integrity.lua`, pathfinding and adjacency tests. |
| P1 | Oribos incorrectly advertised covenant-zone portals and overland links, with several later destinations attached to the wrong floor. | Replace them with the translocation pad, discovered upper-floor flights, and explicit upper-floor portal/jump actions. Source-backed regression tests cover locked and available paths. |
| P1 | Keeping only one representative flight master per zone omitted real island ingress, including Amani’Zar to Tokka’s Landing. | Include explicit discovered-endpoint flight connections, using native taxi IDs and derived estimates where measured durations are unavailable. |
| P1 | Map clicks changed the map ID without projecting the normalized coordinates. A destination could move to a different location. | Shared `ResolveMapPosition` projects through Blizzard world coordinates; it keeps the original point when projection is unavailable. Map-click and native-waypoint adapters use the shared result. `test_map_click_integrity.lua`. |
| P1 | Flight states were interpreted backwards: current master (`0`) was excluded while unreachable (`2`) could count as discovered. Discovery of any master in a zone unlocked the modeled master. | Use discovery API when available, correct the enum fallback and match the modeled master location. `test_routing_integrity.lua`. |
| P1 | Parallel methods to the same destination replaced one another by iteration order; refreshing weights could change earlier returned route results. | Retain alternatives and choose the cheapest current edge while preserving result snapshots. Graph and routing regressions. |
| P1 | Collapsing a final walk into a teleport/portal hid the required walk from the landing point to the target. | Preserve the final walking instruction and its own destination. Updated route-feature regressions. |
| P1 | Quest tracker buttons ranked teleports by same zone/continent, independently of travel time and the next actionable route step. | Use the actual calculated quest route and offer its first teleport only when it is the next action. UI/security regressions. |
| P2 | A same-zone route could mark early actions complete simply because a later step ended on the current map. | Conservative progress highlighting keeps required same-zone actions visible. `test_ui.lua`. |
| P2 | Equipment button configuration lacked a combat guard. Reused equipment callbacks and secondary mouse clicks could trigger unintended actions. | Guard protected changes, clear recycled action handlers, reserve secondary clicks for navigation, and use Blizzard's secure combat visibility driver. `test_ui_security_regressions.lua`. |
| P2 | Malformed SavedVariables roots crashed initialization; NaN/infinite/out-of-range settings reached frames and cost calculations. | Recover invalid roots, validate enum settings, clamp supported ranges and replace nonfinite values. `test_review_settings.lua`. |
| P2 | Choosing an unreachable map point could leave a pending route to a previous target. | Clear the pending result and retain the explicitly requested target, so an unrelated tracked quest cannot replace it. `test_map_click_integrity.lua`. |

Additional dungeon reliability fixes make Journal rescans idempotent, restore the selected Journal tier, keep entrance coordinates paired with their source map, and expose verified static entrances even before the Journal supplies tier metadata. Quest fallbacks no longer choose a zone midpoint or an arbitrary entrance on a map containing multiple dungeons. Hearth landing nodes cannot alias a city node just because the inn and city names match. Cross-zone walks remain alternatives to cooldown-bound teleports.

The new tests reproduce these behaviors rather than treating the baseline's output as the correctness oracle. Some older assertions required the faulty behavior (fabricated connectivity and hidden final walks); those assertions were replaced with executable-route requirements.

## Added destination and travel workflows

- **Currency vendors:** an included, indexed retail catalogue supplements character-specific merchant observations. Selecting a currency opens its vendors and, when candidates are available, an option to compare estimated travel time. Faction, class, race, level, prerequisite groups, profession and reputation conditions filter sourced offers. Saved observations are bounded to 500 total and filtered to the observing character and faction. Asynchronous comparisons restart on movement and stop after repeated drift; choosing another destination cancels stale work.
- **Quests and NPCs:** the AllTheThings catalogue supplies independently sourced NPC coordinates and quest reference locations. Quest-giver records require a join to a separately located giver NPC, with both sets of access restrictions preserved. Generic quest coordinates are never relabeled as objectives or turn-ins. Live Blizzard quest data supplies the current objective/turn-in. Search supports source names, available translations and IDs; `/qr quest <ID> target` and `/qr quest <ID> giver` expose the two workflows. The [destination data notes](DESTINATION-DATA.md) explain the incomplete global translation coverage.
- **Multi-destination trips:** paste up to 20 validated `/way` lines or import TomTom's active points. A directed Held-Karp solver finds the exact minimum open tour in the reusable-route cost matrix for up to ten stops; larger trips use bounded multi-start search and directed segment improvements. Work yields between route calculations and solver batches. Quest-tracker refreshes also calculate one quest route per frame, with cancellation and movement/graph-aware caches. The matrix excludes personal teleports and uses phase/access state available during comparison; its optimum is an estimate, not a claim of globally optimal cooldown/phase scheduling. Every executable leg is recalculated using the actual character. Pending trips persist per character and resume explicitly.
- **Phase-aware routing:** search state includes the relevant zone phases, allowing a location to be revisited after an explicit Zidormi conversation. Seven sourced regions are covered. Phase-specific map IDs cannot be crossed through an ordinary overland edge to bypass a switch. Unknown access does not grant a portal; the visible phase panel distinguishes client evidence, session assumptions and unknown state. Assumptions cannot mark a conversation complete.
- **Access and shortcuts:** attributed fixed portals include conditional unlocks, Druid Dreamway and hidden NPC shortcuts. Legacy coarse duplicates are suppressed only when constructing the graph; public destination lists and independent ships/zeppelins remain available. Calendar-backed shortcuts require synchronized event data and the actual event interval.
- **Teleport destinations:** ownership and usability checks cover engineering toys and real learned dungeon reward spells. The catalogue includes all 31 reference Mole Machine destinations with individual discovery requirements, faction-specific garrisons/shipyards and supported selectable wormhole destinations. Existing verified landing data is preserved. Return to Camp uses the observed successful Make Camp location. Housing uses the owned-house API identity and observed plot coordinates, with Blizzard's secure `teleporthome` action. Menu teleports show the option to select.
- **Uncertain destinations:** Draenor wormholes and other random landings remain usable from the inventory but are excluded from deterministic routing. Hearthstones need an observed bind, camps an observed creation, and housing a known plot. A random landing is not replaced with a zone midpoint.
- **Movement and UI:** estimates check the character's riding/flight capability and measured movement values where available. Route cards preserve the final walk and show phase/choice actions. The trip and phase windows fit the screen, use native checkbox textures and expose their controls in the route toolbar. Native retail Settings integration remains. Saved window anchors are validated before frame APIs receive them.

## Data provenance and maintenance

The destination extractor parses supported literal Lua constructor forms; it never executes upstream Lua. It rejects a source checkout that differs from the pinned revision and records input hashes, the name-source tree, the retail build and excluded dynamic/unavailable branches. Inherited prerequisite groups preserve their required completion counts. Unsupported callbacks, timed/dynamic content, removed/future branches and unsafe expressions are excluded rather than losing their restrictions.

Sources and full licenses ship with the addon:

- [AllTheThings](https://github.com/ATTWoWAddon/AllTheThings/tree/8809863ca3e6e4cb4bf8f2cae1d18d52fc209235): [license](../QuickRoute/Licenses/AllTheThings-MIT.txt), [input manifest](../QuickRoute/Data/DestinationCatalog.sources.txt), [reproducible extractor](../scripts/generate_destination_catalog.py).
- Mapzeroth: [attribution and source notes](../QuickRoute/ThirdParty/Mapzeroth-NOTICE.md), [full license](../QuickRoute/ThirdParty/Mapzeroth-LICENSE.txt).

The addon has no runtime dependency on either source addon and performs no network fetching. The generated catalogue contains 1,042 vendor offer/location variants across 76 currencies, 25,183 quest reference points, 1,496 giver entries joined to independent NPC coordinates, and 8,076 NPC points. It covers 22,211 distinct quest IDs and 5,726 NPC IDs. See [destination data notes](DESTINATION-DATA.md) for extraction rules and update instructions. Catalogue coverage is bounded by the source and extractable semantics. Global catalogue searches use English source names and translations already resolved during display; an unseen translated name can have no match even when the client can supply that title. The later workflow changes explain the English-name/ID fallback in the UI.

## Practical limits and retail acceptance

“Any map point” means the addon accepts a valid map coordinate and attempts a route through the known travel network. It does not compute a terrain collision path around every wall, cave or locked interior. Dungeon routes lead to entrances; they are not full dungeon navigation meshes. Actual timing depends on loading, movement, transport waits and access state that may not be exposed by Blizzard.

Unknown quest objectives/turn-ins, moving NPCs, random teleport landings and unverified access are not replaced with plausible coordinates. Static reference records are labeled. The multi-stop matrix does not solve resource-constrained global scheduling across changing cooldowns and every phase combination; each traveled leg is validly replanned from current state.

The initial simulator rendered the actual addon [trip window](../screenshots/multi-route-review.webp) and [phase window](../screenshots/zone-phases-review.webp) against Blizzard UI code and local client assets. These are historical captures from the earlier simulator build, before the four requested simulator changes were combined. That run exposed a missing checkbox glyph, replaced with the native texture, and reported baseline Blizzard compatibility errors. The [later visual pass and simulator provenance](PLAYER-WORKFLOW-REVIEW-2026-09-05.md#visual-simulator-provenance) document the combined build and its clean startup. Neither set of renders certifies protected travel or pixel-perfect behavior in retail. Follow [retail acceptance](RETAIL-ACCEPTANCE.md) before publishing a release advertised as fully validated in game.

## Security boundary and evidence limits

The runtime is a WoW addon sandbox. The reviewed input surfaces are SavedVariables, TomTom waypoint tables, Blizzard API responses, pasted waypoint text and secure action construction. There is no addon-message receiver, general imported-code evaluator or arbitrary network client in the reviewed addon sources. No confirmed remote exploit was established in these surfaces. This is a scoped conclusion, not a clean bill of health for all dependencies, the game client or future releases.

The principal confirmed action-safety issues were protected-frame mutation and unintended activation through recycled callbacks/secondary clicks; these are reported above as runtime correctness/reliability issues. User labels stay display data. CI actions are pinned to commit hashes; release secrets are passed through environment variables. This pass did not publish a release or perform a separate exhaustive supply-chain scan.

## Historical validation snapshot

The following results were recorded during the initial routing implementation. They remain evidence for that snapshot and should not be quoted as the final assertion counts or final visual validation. Later workflow regressions and simulator evidence are recorded in the [follow-up review](PLAYER-WORKFLOW-REVIEW-2026-09-05.md).

- **Lua 5.1:** 15,184 assertions passed, zero failed, in both discovery and reverse file order. Both orders matter because tests share the mock runtime.
- **Python:** 47 generator and packaging tests passed, covering parser safety, inherited access semantics, NPC/giver coordinate provenance, deterministic generation and complete distributable archives. Missing XML files or required licenses block packaging.
- **Luacheck 1.2.0:** zero warnings and zero errors across 103 Lua files. Whitespace checks passed.
- **Dungeon topology:** all 203 recorded entrances have a route for each faction in the explicit unlocked-quest, selected-phase and discovered-flight fixture. This establishes graph reachability under those prerequisites, not that every character has that access or that all entrances were visited in game.
- **Optimization correctness:** the directed tour solver matches independent exhaustive search on asymmetric matrices, including a case where greedy next-stop selection takes a large detour. Reusable route contexts retain live access checks and recover from failed queries without changing the real player or graph.
- **Transport coverage:** 207 supplementary transport records produce 232 nodes: 174 portals/pads, 25 fixed flights, seven Zidormi changes and one Maw jump. The complete measured graph has 506 nodes and 15,385 edges.

Historical standalone Lua CPU measurements on this workstation after the routing-context isolation fix: 25 one-shot hypothetical comparisons took 614 ms; the same comparisons with a reused context took 145 ms, plus 9 ms of one-time setup (about 75% less CPU including setup). Twenty-five warm live routes took 162 ms. A broader 380-leg comparison across 20 distinct zones took 6.7 seconds of CPU, distributed across frames. Complex phase searches reached about 57 ms per query: yielding between comparisons reduces sustained blocking but does not guarantee a sub-16-ms frame. These are mock-runtime measurements, not retail frame-rate promises.

The catalogue loaded in 88 ms with about 22.5 MiB added Lua memory; lazy indices added about 8.2 MiB in 29 ms. Initial text search took 8.5 ms in the measured sample, with cached refinements faster. See [destination data notes](DESTINATION-DATA.md) for context and repeatable data generation.
